# Selected project research and event-aware Brief — local runbook

Local/synthetic package D13/D15a–c/D17/D18. See
[design](../verification/DAILY-package-07-design-20261014.md) and
[execution ledger](../verification/DAILY-package-07-D13-D15-D17-D18-20261014.md).
Formal design/human, real provider/account/client/visual/CI/usefulness gates
remain separate. No Mini App, automatic repo edit, task, schedule or external
effect is introduced.

The native local entry supports «Глубоко исследуй retrieval cache». Without
a model planner it reads the selected archive, then at most one deterministic
gap query if the bounded first read lacks owner-question coverage. A registered
typed research plan can select archive/web/the already configured repository.
The public question must be a standalone public formulation; private mail,
archive or project wording cannot be projected into public discovery. Model
planner output does not grant any source or provider permission.

For a deterministic synthetic reproduction the explicit v2 shape is:

```json
{"schema_version":2,"question":"retrieval cache","steps":[{"source":"archive","query":"retrieval"}],"gap_steps":[{"source":"archive","query":"cache"}],"coverage_terms":["retrieval","cache"],"max_tool_calls":2,"deadline_seconds":180}
```

This can follow `/deep ` as an emergency/diagnostic command. V1 stored plans
remain readable. The job stores gather/gap/synthesis/verify observations and
exact intermediate refs. `coverage_sufficient` means exact lexical evidence
coverage; accepted factual answers still use the separate D14 verifier.
`tool_call_limit`, `source_conflict`, `source_unavailable_or_unknown` and missing
terms remain visible. Tool-call totals are conservative read-call bounds; they
are not actual billing or provider quality.

An expired research lease goes through existing kind-filtered queue recovery
and retry availability. Prepared reads become `source_outcome_unknown` and
stop extra reads. A completed read is reused only after current source checks.
An explicit `/deepcontinue RESULT_REF VERSION` binds the exact stored digest
and makes new reads under the same source catalogue. A natural continuation
requires an exact research-result focus. Changed selection, stale version,
deletion and expired/revoked grants cannot become a broader new search.
Original Telegram edit/deletion lineage remains bound at continuation intake
and execution. An unresolved read or synthesis operation requires reconciliation,
including durable attempts missing from an interrupted packet. Recovery does
not allocate a fresh model request for an unknown attempt.

Selected public GitHub config supports `repository_ref`, requested `ref`,
`upper_bound`, up to six safe `paths` and explicit `issues`/`pulls`/`releases`
IDs (up to nine selected objects total). Each read resolves and displays the
observed40-character commit; branch movement invalidates file cache selection.
Files use SHA-bound URLs and line spans. Issues/PR/releases carry current object
versions and an explicit mutable-object label, not a false commit snapshot.
Secret/dot/generated/traversal paths are excluded; repository code never runs.
Missing paths/access stay partial, with no inferred private404 diagnosis.

The private read-only credential contract is separately injected and exercised
only with fake tokens in an isolated vault/connection fixture. No private key
is loaded from general runtime config. Provisioning a selected fine-grained
or App-installation token, checking actual repository permission width, token
minting/rotation and live canary require their own account scope. Read permission
does not authorize model transmission: `research.synthesis.github` needs an
independent provider/connection/data-class grant for that exact repository.
Disconnect/revoke waits for the current bounded HTTP credential lease; both
legacy and v2 results retain actual private resource classification.

GitHub API shape/version/permissions were checked against primary documentation
on2026-10-14: [contents](https://docs.github.com/en/rest/repos/contents),
[issues](https://docs.github.com/en/rest/issues/issues#get-an-issue),
[pull request](https://docs.github.com/en/rest/pulls/pulls#get-a-pull-request),
[release](https://docs.github.com/en/rest/releases/releases#get-a-release).
Documentation reads are not live adapter/account validation.

Brief enumerates the bounded whole window, creates deterministic event groups
before its model packet, and keeps all received source/version pointers in the
immutable material inventory. Canonical URL plus exact content distinguishes
corrections; similar wording and truncated candidates remain uncertain.
Reposts never increase a verified independent-confirmation count. Event history
observes previously included owner Briefs, with last-surfaced/read/usefulness
unknown. Revoked/deleted history cannot authorize current source reads.

Importance, novelty, reliability, exact project applicability and reading cost
are separate signals. Source/channel fairness prevents an archive flood from
erasing a small selected source. Up to five source-bound stories and three
optional continuations are shown. Quiet/partial weeks are valid. A possible
experiment includes the current confirmed relationship and rejection condition;
keyword/name overlap alone is weak context. Model wording must pass D14 fact
proof and cannot replace deterministic selection, project identity or next-step
authority. A suggestion creates neither an obligation nor a schedule.
Local facts/titles also pass D14 proof; unsafe or unsupported shortenings use
neutral source wording, and an unrepresented required event stays an explicit
coverage gap. Native archive/project matching needs canonical post ID, content
hash, source URL and an exact cited immutable result, not name/keyword overlap.
Only actually included project stories contribute persisted current version/
digest/expiry bindings. Loads, exports/materials, result provenance and final
delivery/reader guards reject changed/expired context after restart.

Packet selection, editorial inclusion and surfaced/read state are separate.
Only editorial inclusion enters recurrence history. Research coverage evaluates
the same eight-item/1200-character source/span projection as synthesis; gathered
coverage is a separate observation. Neither lexical coverage nor deterministic
grouping establishes semantic sufficiency or measured owner usefulness.

Use `/briefmaterials BRIEF_ID VERSION OFFSET` to inspect omitted records and
duplicate/event revision reasons. Changing renderer does not generate new facts.
Current synthetic event packet compares exact member sets for seven authored
dev events; its perfect small-fixture counts are not owner gold or holdout.

Rollback disables new planning/selection paths or reverts source changes while
preserving immutable results, unknown/read/effect receipts, tombstones,
revocations and canonical IDs. Do not reset/replay ledgers or install services.
