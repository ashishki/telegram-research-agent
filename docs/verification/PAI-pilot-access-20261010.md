# Текущий пакет пилота — 2026-10-10

Авторизация: текущие поручения владельца и ADR-018. Кандидат для независимой
проверки — fa7857b; основной runtime совпадает с проверенным 2e541af. Этот
документ описывает конкретный следующий сеанс, но не создаёт согласие на
невыбранный аккаунт, получателя, частные данные или production.

## Что уже можно проверить

- Реальные Go inference на полностью синтетических пользовательских данных и
  источниках через native ingress/worker/PG. Выбраны DeepSeek V4 Flash для
  генерации и DeepSeek V4 Pro для независимой оценки полных диалогов.
- Публичные источники через существующие scoped adapters: pytest-dev/pytest,
  README.rst, точный ref e4f7f174bc4a1686b31639d29a3e211941390979; документация
  Python unittest на docs.python.org. Это fetch/exact-ref, не доказательство
  поисковой выдачи Brave.
- Natural Watch/Act на синтетических внешних эффектах и текущие native
  HTML/PDF/Markdown через приватный renderer. Это не живая Telegram-доставка.

Никаких модельных запросов с действительным личным архивом или почтой в этом
сеансе. Оригинальный отказ115 GoUsageLimitError сохранён. После сообщения
владельца «включил экстра юзадж, пробуй» выделен отдельный запрос116; он не
перезаписывает115 и не является автоматическим повтором неизвестного исхода.
Стоимость при отсутствии billing telemetry остаётся неизвестной.

## Недостающие конкретные подключения

| Область | Что должно быть выбрано | Первый проверяемый шаг |
| --- | --- | --- |
| Telegram | test bot/key reference, private owner/actor/chat tuple, destination, foreground delivery scope | одна точная контрольная фраза; настоящий message_id и совпавший получатель |
| Microsoft mail | выделенный test account, одна test folder, срок доступа, read/write/reconcile отдельно, контролируемый адресат | read metadata синтетических test messages; затем точный preview одного письма |
| Calendar | конкретный test calendar, read/create scopes отдельно, timezone, временное test event | read выбранного окна; затем preview создания одного события |
| External discovery | выбранный Brave credential reference и public query/hosts/call budget | один search и ограниченный fetch первичных источников |

Вопрос о выбранных подключениях отправлен владельцу; ответ с настройками ещё
не получен. Указать безопасный путь к приватному описанию, без ключей в чате.
Аккаунты/IDs и provider receipts сохраняются вне Git. Существующие подходящие
grants использовать; не просить повторное общее разрешение вместо недостающей
конкретики. UTD/Canvas API по договорённости отложен.

Предлагаемый первый connected canary: один foreground сеанс, до20 задач,
только выбранные тестовые аккаунты с синтетическим содержимым, без расписаний
служб/таймеров. Реальные личные данные и длительность ежедневного пилота требуют
отдельно выбранных source/retention/model scopes. Истечение, revoke и cancel
проверяются как отдельные сценарии. Смена аккаунта не переносит grants.

Для Telegram контрольная фраза: «Контрольная проверка персонального ассистента».
До отправки предъявить выбранный bot/destination/owner и полный текст. Для
mail/calendar предъявить полный адресат/тело или календарь/start/end/timezone,
expiry и version-bound confirmation. Unknown/202 не повторять: только отдельная
сверка тем способом, который действительно поддерживает провайдер.

## Исполнимые пути и границы

Существующий CLI: `PYTHONPATH=src .venv-pai/bin/python -m prm.cli --help`.
Он действительно содержит `runtime-status`, `runtime-tick`,
`runtime-research-worker`, `job-worker`, `job-status` и `job-result`, с явными
конфигурациями. Не существует универсальной команды connect-all.

Текущий PostgreSQL adapter — SyntheticTarget: localhost, отдельный port/database,
marker pa-synthetic и непривилегированные pa_test роли. Он предназначен для
разрешённых синтетических тестов; его нельзя переименовать в production target
или выдавать за защищённое постоянное хранилище личных аккаунтов. До сеанса с
личными данными нужны конкретные private-storage/access решения PAI-27/28.
Никаких production migrations или фонового polling здесь не запускается.

Действительные команды текущих публичных/синтетических проверок записаны в
датированных receipts и итоговом отчёте. Команды живых источников будут
составлены на выбранных приватных конфигурациях; неизвестный путь/аккаунт нельзя
заменять фиктивным параметром и объявлять выполненным canary.

## Двадцать операторских задач

1. Начать диалог и получить полезный первый шаг.
2. Переписать текст, сохранив исходный срок.
3. Сократить предыдущий ответ.
4. Сделать его менее официальным.
5. Исправить адресата, сохранив остальные условия.
6. Сменить тему и проверить отсутствие прежней подстановки.
7. Вернуться к текущему результату.
8. Выбрать пункт из ответа.
9. Проверить отказ при неоднозначном «да».
10. Отменить незавершённую задачу.
11. Найти точные архивные подтверждения.
12. Проверить RU/EN retrieval и отсутствие неподтверждённых чисел.
13. Прочитать свежий первичный источник и показать ограничение покрытия.
14. Сравнить материалы репозитория на точном ref.
15. Создать weekly Brief, обновить и сопоставить версии.
16. Прочитать Brief на телефоне, в HTML и PDF.
17. Подтвердить Watch, проверить реальный tick, паузу/revoke и отсутствие новых отправок.
18. Прочитать выбранные test mail/calendar данные без расширения области.
19. Получить точный preview действия и исправить его до подтверждения.
20. Подтвердить один эффект, сверить receipt и повторить нажатие без второго эффекта.

Операторские ответы и приватные screenshots — вне Git. Измерить полезность,
пропущенные обязательства, ложные утверждения/отказы, notification noise,
latency и стоимость за полезный результат отдельно. В synthetic benchmark
записывать только фактически пройденные случаи; этот список не является PASS.
Model judge не заменяет человеческий пилот, безопасность или приёмку продукта.
