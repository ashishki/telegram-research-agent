# PRM Search And News: acceptance evaluation

Status: planned; independent human labels and live measurements are not available.

## Компактный benchmark: 28 сценариев

Использовать существующие `test_prm_intent_archive_contract`, `test_prm_application`, `test_prm_bot_dispatch`, claim/synthesis tests, `test_prm_post_answer_actions`, watch fetch/shadow/profile/delivery, `prm_replay_query`, QA v2 и product UX evaluator. Добавить недостающие assertions/fixtures к этим путям, не отдельную платформу evals. Сохранять final rendered text и ожидаемое поведение, а не только внутренний route/metric. [QA v2](https://github.com/ashishki/telegram-research-agent/blob/cee8baae3b8a41f571bd689f2dadf7e6e981863f/tools/prm_qa_eval_v2.py), [UX evaluator](https://github.com/ashishki/telegram-research-agent/blob/cee8baae3b8a41f571bd689f2dadf7e6e981863f/tools/prm_product_ux_eval.py), [replay](https://github.com/ashishki/telegram-research-agent/blob/cee8baae3b8a41f571bd689f2dadf7e6e981863f/tools/prm_replay_query.py).

Ниже **проект набора**, не уже размеченные 28 наблюдений. D01–D20 — dev, H01–H08 — спецификация будущего закрытого holdout. Holdout должен составить владелец/отдельный разметчик из иных вопросов и источников; его точные тексты, expected evidence и оценки не использовать в разработке. Этот отчёт не создаёт независимость самим словом holdout. Пограничные ошибки берём из настоящих regressions, а не только из удобных для реализации шаблонов.

| ID | Сценарий | Ожидаемый результат / обязательная проверка |
|---|---|---|
| D01 | Архив: agent evals + «применимо сейчас» | Прямой архивный ответ, source-backed рекомендация, нет внешнего вызова/неявного проекта |
| D02 | Точная фраза/название против разнесённых слов | Exact источник на первом месте, слова по отдельности не считаются точной фразой |
| D03 | RU-вопрос, EN-материал и обратный вариант | Найдены ожидаемые прямые материалы; перевод не меняет утверждение |
| D04 | Одна опечатка в термине | Осторожный rewrite помогает, исходная задача сохранена; unrelated не становится direct |
| D05 | Прямые и смежные материалы; «только прямые» | Только direct в основном ответе, coverage по вопросам; нет повторов одного поста |
| D06 | Сравнение двух подходов по архиву | Одинаковые критерии; пробел второго варианта виден, ложного победителя нет |
| D07 | Обычный вопрос precision/recall | Полезное объяснение без неявного проекта/притянутого архива |
| D08 | Полностью пустая выдача | Нет выдуманных материалов, один понятный способ продолжить |
| D09 | Текущая цена, найден только старый пост, web запрещён | Старое число не выдано за текущее; никакого egress |
| D10 | Свежая версия с разрешённым web и первоисточником | Прочитана нужная страница; версия/дата/URL подтверждены; один источник достаточен |
| D11 | Смешанный запрос: архив + web timeout | Архивная полезная часть сохранена; внешняя часть ограничена; dispatch не падает |
| D12 | Два источника противоречат по числу/дате | Обе версии с provenance; нет выдуманного разрешения конфликта |
| D13 | «подробнее → за неделю → что применить» | Тема та же, окно реально фильтрует, рекомендации отличимы от фактов |
| D14 | Явная тема B после A и новое «подробнее» | B без утечки темы/фильтров A |
| D15 | «Сохрани второй» + confirm/cancel/repeat | Точный пункт/источники в preview; cancel без canonical write, confirm один объект |
| D16 | TTL/restart/старая кнопка/другой chat | Честное отсутствие контекста, owner/version/expiry checks, нет чужой записи |
| D17 | Верный текст, неверный URL; цитата отсутствует | Цитатная связь не подменяется найденным lexical ref; исправление/fallback до публикации |
| D18 | Цена 20→900, «не»→утверждение, другой субъект, изменённая цитата | Каждая мутация отдельно; неподдержанный ключевой факт не публикуется. Парный правильный ответ остаётся полезным |
| D19 | Короткий факт и неверное 11-е утверждение | Проверка не объявляет успех из-за 0/10-limit; непроверенный остаток не выпускается |
| D20 | Дайджест: дубль, старый репост, косметическая правка, настоящее исправление | Одна карточка на событие; старое не новое; исправление с diff к доставленному выпуску |
| H01 | Другие темы, RU/EN и редкая опечатка | Независимая проверка релевантности/полезности и отсутствия переобучения aliases |
| H02 | Иной архивный вопрос с «сейчас» и смежной находкой | Правильный scope, useful partial; нет лишнего web или total refusal |
| H03 | Иной текущий факт с достаточным единственным источником | Успешный ответ с правильным временем проверки; без требования двух ссылок |
| H04 | Новые перефразы/числа/отрицания/акторы | Различить полезную перефразу и искажение; не просто совпадение токенов |
| H05 | Страница с injection, private URL и redirect | Данные не расширяют полномочия; секреты/архив наружу не уходят; безопасная часть доступна |
| H06 | Новая подписка: preview, cancel, confirm, expiry, unsubscribe | Черновик полезен; до confirm нет poll/send; после confirm только точный scope; отмена гасит queued sends |
| H07 | Отказ источника против здорового «нет новостей» | Не генерировать ложную отмену/пустой success; health и notification cap корректны |
| H08 | Две доставки одновременно, timeout, restart, quiet hours | Нет локального double-send при reservation; pending не теряется; ambiguous=unknown, caps/timezone соблюдены |

Один сценарий может быть многоходовым и иметь несколько парных perturbations. Число ответов/claims/deliveries учитывать отдельно от числа сценариев; 28 — не знаменатель всех метрик. Для H06–H08 допускаются независимые deterministic labels по состояниям; «это мне полезно» размечает человек.

Для relevance: независимый pool top-10 разных configs + ожидаемые документы, blind/random order, категории direct/useful-adjacent/irrelevant и source groups. Для accuracy: человек читает первоисточник и финальный текст, выделяет все существенные claims, их spans, даты, числа, отрицания, субъект, цитаты. Автоматические validators и LLM judge помогают найти кандидатов на ошибку, но не заменяют эти labels. Owner usefulness отделяется от проверки факта; один и тот же ответ может быть верным и бесполезным.

## Стартовые пороги — гипотезы для принятия решения

| Метрика | Знаменатель и измерение | Предлагаемый стартовый допуск |
|---|---|---|
| Полезность | Все answerable cases по независимой разметке; слепая оценка 1–5: задача решена, понятно, применимо | ≥80% с оценкой ≥4; минимум 16 answerable сценариев, отдельно показать частичные ответы. Для 16 это минимум 13 |
| Ложный отказ | Answerable cases, где ответ заменён отказом/бесполезной границей при доступных разрешённых evidence | ≤10%; на малой выборке показать целое число ошибок |
| Релевантность | P@5 по оценённым кандидатам; nDCG@5 по graded labels; recall@10 по проверенному expected set | P@5 ≥0.80, nDCG@5 ≥0.85, recall@10 ≥0.90 на dev; по сегментам, без смешения с частотой терминов |
| Поддержка финальных фактов | Supported published factual claims / все опубликованные factual claims по человеку; key claims помечены заранее | ≥0.98 в целом; ни одного критического unsupported/contradicted key claim в наборе |
| Цитаты | Видимые связи claim→source, которые действительно подтверждают текст / все видимые citation edges; coverage отдельно | Precision ≥0.98; у всех ключевых source-dependent фактов корректная ссылка; HTTPS-format считать иной метрикой |
| Полнота проверки | Проверенные factual clauses / все factual clauses, выделенные человеком | ≥0.95 в целом, 100% ключевых; zero-claims и truncation не считаются успехом |
| Свежесть | Вопросы с актуальным фактом и новости с известным временем | 100% корректных scope/date provenance; 0 старых репостов как новых, 0 старых цен как текущих |
| Диалог | Правильно выполненные ожидаемые переходы / все размеченные transitions | ≥90%; 100% для owner/scope/confirm/cancel и отсутствия ложного сохранения |
| Дайджест | Полезные карточки / доставленные карточки; повторные события без значимого diff / все карточки | ≥80% полезных; ≤5% повторов, в deterministic duplicate fixture — 0. Completeness оценивается отдельно по важным событиям |
| Шум | Ненужные по owner карточки / все карточки; неожиданные уведомления / все отправки | ≤10% ненужных в ограниченном пилоте, 0 вне согласованных caps/quiet hours |
| Доставка | Pending, attempts, sent, failed, unknown по всем разрешённым edition/event keys | 0 потерянных pending в fault tests; 0 локальных гонок; все ambiguous видимы. Это не exactly-once |
| Latency | От принятия update до завершения отправки; p50/p95, отдельно cold/warm, local/model/web и ошибки | Гипотеза: local 1/3 s, synthesis 6/15 s, web 10/30 s; выпуск 20/60 s. Минимум 50 запросов на сравниваемый путь для пилотной оценки |
| Стоимость успеха | **Все** расходы периода, включая неудачи/retries, / число ответов или выпусков с useful pass | Гипотеза: archive ≤$0.04, web ≤$0.10, выпуск ≤$0.20; общий месячный cap согласуется отдельно |

В таблице SLA latency записан как p50/p95. Время очереди/планирования выпуска измерять дополнительно; нельзя скрыть его временем одного вызова модели. Token/cost receipts содержат модель, количество и тарифную версию, без raw private prompts. Превышение денег/времени приводит к полезному частичному ответу и прекращению следующих платных стадий.

При 28 сценариях дробные проценты нестабильны: показывать также абсолютные счётчики и неопределённость; не объявлять 98% мировой точности по 50 claims. Ноль критических ошибок — необходимое наблюдение в этой выборке, не гарантия вне неё. Порог нельзя поднимать/опускать после просмотра holdout ради красивого pass; спорные labels отдельно разрешаются человеком.
