# PRM-MAT-7 implementation evidence

Status: scoped durable interaction-ledger implementation in temporary SQLite
fixture databases only. This is not a PRM-19 dogfood start, operator
validation, release claim, public telemetry export, production migration, or
production database write.

## Scoped outcome

- Added `prm_interaction_ledger` with one privacy-safe receipt per durable
  post-answer context. It stores only hashed chat identity and bounded answer
  metadata; it has no columns for raw question, Telegram post text, source URL,
  prompt, completion, or provider payload.
- Added an append-only `prm_interaction_feedback_transitions` audit table.
  Explicit feedback buttons update the matching interaction at most once;
  replay remains a no-op for the ledger while the pre-existing confirmation
  proposal lifecycle remains intact.
- Retention is enforced at 90 days. Before ledger write, feedback, owner-scoped
  review, or aggregate export, expired transition rows and then expired ledger
  rows are deleted transactionally. Owner review is chat-hash scoped; aggregate
  export returns counts only and is marked local/private.
- The production PRM callback path has no volatile context fallback. For a
  pre-MAT-7 proposal schema or unavailable ledger, receipt-status recording is
  best-effort so answer actions remain available and the receipt cannot break
  the answer path.
